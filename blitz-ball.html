A versus arcade game where two players fight to score by making the ball bounce across the arena.

Gameplay Programming

Built in Unity 6 with the Universal Render Pipeline. The codebase is split into four independent systems: player control, ball states, level states (the main loop), and a game state machine driving all interfaces.

Architecture · Overview

Systems & tooling

The project is organised around clearly separated systems, with tooling chosen to keep the code concise and maintainable.

  • Four independent systems: player control, ball states, level loop and a UI-driving game state machine
  • Input handled through Unity's New Input System for flexible, straightforward input code
  • Developed in JetBrains Rider 2024 with GitHub Copilot to streamline repetitive code and refactoring

Physics · Setup

Physics-driven ball & movement

The game runs on Unity 6's built-in physics; every in-game object uses a Rigidbody for its calculations.

  • Default Contact Offset lowered from 0.2 to 0.01 for more precise, less recursive contacts, fixing several ball/player collision bugs
  • The player moves by scaling its speed against the left-stick Vector2 and applying it to velocity
  • The ball is propelled along the player's forward vector with a force derived from attack charge, base power and its current velocity, so it never slows down
  • Walls use a frictionless physics material so the ball keeps all its speed on rebound

Input · Local multiplayer

Controller assignment

Controller pairing runs in three steps to reliably bind each gamepad to its player.

  • On connection, a new gamepad is registered as a pendingController
  • It is identified through Unity's Gamepad HashSet to know which player it belongs to
  • The controller is then linked to all its dependent objects; a reconnecting pad is recognised and re-assigned to the same player

Ball · State machine

Ball states & events

The ball is driven by a state machine that emits events the rest of the game reacts to.

  • Dropped (initial), Caught (moves to the player's "hand" along an animation curve), Flying (neutral, gravity-free, constant motion) and Hit (brief, collisions disabled to avoid self-hits)
  • Events: OnBallCaught, OnHit, OnHitStateStart, CaughtStateEnd, OnNeutralBounce, OnBallFlight
  • Tunable variables: min/max propulsion speed & height, linear damping/mass, player immunity time, ball owner and a speed floor that rises with each velocity increase

Player · State machine

Player states

The player is also a state machine, switching states from inputs.

  • Neutral: movement only, the gateway to every other state
  • Sprinting: faster movement via a sprint boost, but the player can't hit or grab
  • Hit: swings the bat while still moving freely
  • Grab: pulls a nearby ball toward the player, with duration and range scaled by the grab charge

Levels · Scene management

Multi-scene loading & goals

A multi-scene setup lets a single Level Manager work across every level without reconfiguration.

  • A container scene holds the shared objects (Level Manager, UI, floor, lighting) and loads the level scenes on start
  • Levels are pre-loaded then deactivated; only the current level's objects are activated via its build index
  • Goals are assigned per level: a math function reads the goals list and current level to set each player's goalToDefend and goalToAttack
  • Scoring only counts in a player's attack goal; each goal tracks its received points to follow match progress
